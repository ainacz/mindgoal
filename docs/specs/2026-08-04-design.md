# Маршрут — Telegram Mini App: дизайн системы

Дата: 04.08.2026
Статус: согласовано, готово к плану реализации

---

## 1. Что строим

Telegram Mini App, который превращает большую цель человека в маршрут из ежедневных задач на 15—45 минут. Человек вводит цель и срок, ИИ уточняет размытое, формулирует измеримые критерии готовности и пишет маршрут по фазам. Дальше человек каждый день открывает одну карточку и закрывает один день.

### Объём первого среза

Один живой путь целиком: **ввод цели → уточнение → критерии → генерация → экран «Сегодня» → завершение дня**. Плюс экраны «Карта» и «Мои цели» в режиме чтения и удаления.

В первый срез **не входит**: AI-ментор, замена задачи на «телефонный формат», уведомления, платежи, магазин XP, мультиязычность, пересчёт маршрута после пропусков. Каждое из этих — отдельный срез со своей спекой.

### Три решения, определяющие всё остальное

**Маршрут ждёт человека.** `current_day` двигается только при нажатии «Завершить день». Пропустил неделю — вернулся, и день 12 всё ещё ждёт. Дни не сгорают, маршрут не пересчитывается, штрафов нет. Стрик — отдельный счётчик календарных дней подряд: он гаснет, но на маршрут не влияет.

**Генерация скелетом и окном.** Сразу генерируются критерии, фазы и дни 1—7 (около 15 секунд). Остальные дни дописываются батчами по 7 в фоне, по мере приближения. Причина не в деньгах — полный маршрут стоит около цента, — а в латентности, в риске обрезанного JSON на 20 тысячах выходных токенов и в падении качества к концу длинной генерации. Побочный эффект приятный: замки на карте становятся честными — будущего буквально ещё нет.

**Ключ DeepSeek живёт только на бэкенде.** Фронт ходит через наш API.

## 2. Архитектура

Монорепо, две папки:

```
backend/
  app/
    main.py            точка входа, сборка приложения
    config.py          настройки из окружения
    db.py              движок, сессия, базовый класс
    auth.py            проверка initData из Telegram
    models/            SQLAlchemy 2.0, по файлу на сущность
    schemas/           Pydantic — контракт с фронтом и с моделью
    ai/
      client.py        обёртка над DeepSeek: JSON mode, ретрай, учёт токенов
      prompts.py       системные промпты, неизменяемые между вызовами
      clarify.py       уточняющие вопросы
      criteria.py      критерии готовности
      route.py         фазы, скелет, батчи дней
    services/          бизнес-логика: завершение дня, стрик, догенерация
    api/               роутеры, тонкие
  alembic/
  tests/
frontend/
  src/
    api/               клиент, типы из schemas
    screens/           Today, Map, Goals
    components/        Graduation, Sheet, Checklist, DayRow
    lib/               telegram sdk, haptics, confetti
docs/superpowers/specs/
```

Границы простые. `api/` не знает про DeepSeek — только вызывает `services/`. `ai/` не знает про базу — принимает Pydantic-модель, возвращает Pydantic-модель. `services/` знает про то и другое и больше ни про что. Файл длиннее 200 строк делает две вещи и подлежит разрезанию.

### Авторизация

Заголовок `X-Telegram-Init-Data` на каждом запросе. FastAPI-зависимость проверяет HMAC-подпись от токена бота, отвергает `auth_date` старше 24 часов, при первом обращении заводит `User`. Ни сессий, ни JWT, ни рефреш-токенов — подпись Telegram и есть авторизация.

## 3. Модель данных

Семь таблиц. Все id, кроме `User`, — UUID.

**User** — `id` (BIGINT, он же telegram_id), `username`, `first_name`, `total_xp`, `tz_offset_minutes`, `created_at`.

**Goal** — `id`, `user_id` → User, `title`, `category` (короткая метка от ИИ: «Карьера», «Бизнес»), `duration_days` (30/60/90), `current_day` (по умолчанию 1), `generated_until_day`, `status` (`draft` / `generating` / `active` / `completed` / `archived`), `streak_days`, `last_completed_date` (DATE в часовом поясе человека), `created_at`, `completed_at`.

**GoalCriterion** — `id`, `goal_id`, `text`, `is_completed`, `order_index`.

**Phase** — `id`, `goal_id`, `title`, `start_day`, `end_day`, `order_index`.

**DailyTask** — `id`, `goal_id`, `day_number`, `title`, `estimated_minutes`, `description`, `hint`, `is_completed`, `completed_at`, `is_simplified`. Уникальность по паре (`goal_id`, `day_number`).

**TaskChecklistItem** — `id`, `daily_task_id`, `text`, `is_done`, `order_index`.

**AiCall** — `id`, `user_id`, `goal_id` (может быть пустым), `kind` (`clarify` / `criteria` / `skeleton` / `batch` / `simplify` / `mentor`), `model`, `prompt_tokens`, `completion_tokens`, `cached_tokens`, `latency_ms`, `ok`, `error`, `created_at`.

### Два отступления от исходного ТЗ

**`streak_days` перенесён с `User` на `Goal`.** Интерфейс показывает стрик рядом с каждой целью — значит он и принадлежит цели. Глобальное число в шапке — это стрик активной цели, считать его отдельно незачем. На `User` остаётся `total_xp`.

**Добавлены `AiCall` и `Goal.generated_until_day`.** Первая — чтобы видеть расход токенов и убеждаться, что кэш работает: если `cached_tokens` держится на нуле, значит системный промпт где-то плавает между запросами. Вторая — чтобы бэкенд знал границу написанного маршрута, а фронт знал, где ставить замки.

## 4. AI-слой

Все механики — функции одной формы: Pydantic на входе, Pydantic на выходе, JSON mode внутри. Клиент DeepSeek подставляется зависимостью, поэтому слой тестируется без ключа и без сети.

**Модель** — `deepseek-chat` (V4-Flash). Системный промпт для каждого типа вызова неизменен и стоит первым, переменная часть уходит в конец — только так работает кэширование входа, а оно дешевле обычного входа в пятьдесят раз.

**Уточнение.** На вход цель и срок. Если цель конкретна («стать AI-инженером», «купить BMW») — возвращает пустой список вопросов и шаг пропускается. Если размыта («хочу бизнес», «выучить язык») — два-три вопроса, каждый с тремя вариантами ответа для чипов плюс возможность своего.

**Критерии готовности.** Три-четыре пункта, которые можно предъявить: «задеплоен сервис с публичной ссылкой», «пройдено два собеседования». Промпт прямо запрещает формулировки состояния — «разобрался», «появилась привычка», «стало легче». Человек может переписать любой пункт перед генерацией.

**Маршрут.** Скелет: фазы на весь срок плюс дни 1—7. День 1 всегда физическое действие на 15 минут без абстракций — «поставить Python и напечатать одну строку», а не «изучить основы». Батчи: следующие 7 дней с контекстом цели, критериев, текущей фазы и заголовков уже написанных дней, чтобы не повторяться.

**Триггер догенерации.** При завершении дня, если `current_day > generated_until_day - 4`, ставится фоновая задача на следующий батч. Человек этого не видит — у него всегда есть запас открытых дней.

Механизм фона в первом срезе — `BackgroundTasks` из FastAPI, без очереди и без Redis. Инстанс на бесплатном тарифе может уснуть посреди задачи, поэтому батч обязан быть идемпотентным: пишем дни одной транзакцией и двигаем `generated_until_day` только после успешной записи. Недописанный батч просто повторится при следующем запросе — проверка «нужен ли батч» висит на каждом обращении к `/today`, а не только на завершении дня. Очередь появится, когда появится второй инстанс, и не раньше.

### Границы расхода

`max_tokens` на каждом вызове — модель, которую попросили семь дней, иногда пишет тридцать. Ретрай при невалидном JSON ровно один, дальше честная ошибка. Лимит ментора — 20 сообщений в сутки на человека, заложить сразу, хотя сам ментор в первый срез не входит.

## 5. API

```
POST   /api/session              initData → User
POST   /api/goals/clarify        {title, duration_days} → {questions: []}
POST   /api/goals                {title, duration_days, answers} → Goal(draft) + критерии
PATCH  /api/goals/{id}/criteria  правка критериев перед генерацией
POST   /api/goals/{id}/generate  скелет: фазы + дни 1—7, статус → active
GET    /api/goals                список целей
GET    /api/goals/{id}           цель, фазы, дни — для карты
GET    /api/goals/{id}/today     текущий день + чек-лист
PATCH  /api/checklist/{id}       отметить пункт
POST   /api/tasks/{id}/complete  завершить день: XP, стрик, current_day++, догенерация
DELETE /api/goals/{id}           удалить
```

Все ответы — Pydantic-схемы, они же источник TypeScript-типов на фронте.

## 6. Фронт

Три экрана и шторка мастера. Визуальная система согласована и зафиксирована в двух макетах: `marshrut-design-v2` (экраны) и `marshrut-wizard-v2` (мастер).

**Токены.** Фон `#0A0B0D`, линии `#242830`, текст `#EDE7DA`, второй план `#7B8290`, приглушённый `#434A54`, бирюзовый `#6FE3D2`, латунь `#D9A441`. Шрифты: Jura 300/500 на заголовки и задачу дня, системный sans на текст и кнопки, IBM Plex Mono на числа и метки.

**Правила, которые нельзя нарушать.** Одна заливка на экран — главная кнопка. Бирюзовый только для текущего дня и для экрана генерации. Латунь только для стрика. Никаких карточек — структуру держат волосяные линии. Никаких эмодзи и зачёркиваний.

**Сквозной объект — шкала на 90 делений.** Горизонтально в шапке, вертикально на карте, сжато в карточке цели. Пройденные дни костяные и светлеют к сегодняшнему, текущий бирюзовый с кареткой, будущие тусклые, каждое десятое деление выше, границы фаз во всю высоту.

**Состояния, которые надо нарисовать до кода.** Пустой список целей. Маршрут в статусе `generating`. Отказ генерации. Все дни пройдены. День, который ещё не написан.

**Данные.** React Query: `today` и `goals` кешируются, завершение дня инвалидирует обе выборки. Оптимистичное обновление на чек-листе — отметка галочки не должна ждать сеть. Завершение дня — без оптимизма: конфетти и вибрация только после ответа сервера.

## 7. Ошибки

**Генерация не удалась.** Человек видит «Не получилось собрать маршрут» и кнопку повтора. Цель остаётся в статусе `draft` — ничего не потеряно, введённое сохранено.

**Батч не удался.** Человек не видит ничего: у него ещё открыты дни. Попытка повторяется при следующем заходе. Если `current_day` упёрся в `generated_until_day` — на экране «Сегодня» появляется «Дописываю следующие дни» и кнопка повтора.

**Бэкенд спит.** На бесплатном тарифе инстанс засыпает через час без трафика, холодный старт до тридцати секунд. Лечится пингом раз в сорок минут; на экране в это время скелетон, а не пустота.

**Невалидный initData.** 401 и экран «Открой приложение через Telegram» — единственный случай, когда мини-апп не работает вовсе.

## 8. Тестирование

Бэкенд — pytest с `httpx.AsyncClient` и Postgres из `docker-compose.test.yml` (SQLite не годится: используем UUID, JSONB и уникальные составные индексы). Клиент DeepSeek подменяется через `dependency_overrides` на фейк, отдающий заранее записанные JSON-ответы: по одному эталону на механику. Отдельно — тест на невалидный JSON (проверяем ретрай) и на обрезанный (проверяем понятную ошибку).

Что покрываем обязательно: проверку подписи initData, завершение дня со всеми побочными эффектами (XP, стрик, `current_day`, триггер батча), стрик через границу суток в часовом поясе человека, отказ доступа к чужой цели.

Фронт — Vitest на чистые функции: расчёт делений шкалы, форматирование дней. Компоненты в первый срез не покрываем.

## 9. Развёртывание

Фронт на Vercel, база в Supabase, бэкенд на Koyeb — всё на бесплатных тарифах. Ограничения приняты осознанно: Supabase ставит проект на паузу после недели без обращений и даёт 500 МБ; Koyeb засыпает через час простоя. Для разработки и первых пользователей это терпимо. Когда пойдёт живой трафик — переезд на VPS за четыре-пять долларов снимает и паузы, и холодные старты, и переносить придётся только переменные окружения.

Секреты — только в переменных окружения: токен бота, ключ DeepSeek, строка подключения. В репозиторий не попадает ничего, `.env.example` с пустыми значениями.
